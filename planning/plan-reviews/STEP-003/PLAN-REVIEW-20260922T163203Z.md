## Findings

### F-001 — Containment не сохраняется при последующем чтении артефактов

- Severity: high. Category: contract. Location: `planning/tasks/STEP-003.md`, `Implementation plan`, пункт 2; `src/projectModel/manifestService.ts`, `validateManifest`/`resolveContainedPath`.
- Scenario: `detectProject` проверяет configured path один раз и возвращает обычные строки `configuredPaths`. После valid detection каталог или отдельный Markdown-файл заменяется symlink на файл вне workspace, а parser открывает путь из `configuredPaths` без повторной проверки непосредственно перед чтением.
- Impact: расширение прочитает данные за границей owning workspace root вопреки containment contract и принятой read-only модели. Фраза «уже прошедшие manifest containment» ошибочно приравнивает первоначальную проверку к безопасности будущих I/O.
- Fix direction: явно запланировать защищённый read/enumeration seam для каждого artifact, projection и reference input, с проверкой resolved path и типа файла при фактическом чтении, а также tests для static symlink, подмены после detection и после enumeration. Не полагаться только на `ValidProjectState.configuredPaths`.

### F-002 — Invalid manifest не получает watcher и не восстанавливается автоматически

- Severity: medium. Category: contract. Location: `planning/tasks/STEP-003.md`, `Implementation plan`, пункт 5.
- Scenario: workspace первоначально имеет malformed, unsupported или configuration-blocked manifest. План создаёт `FileSystemWatcher` только «после valid detection»; пользователь исправляет manifest, но событие не обрабатывается и состояние остаётся прежним до ручного refresh или перезапуска.
- Impact: не выполняется REQ-009 Acceptance об инкрементальном обновлении manifest без перезапуска Extension Host, а valid index не появляется после исправления ошибки.
- Fix direction: отдельно описать manifest watcher для каждого workspace root независимо от его текущего typed state, с redetection на событие и созданием/освобождением artifact/reference watchers при переходах в valid и из valid. Проверить переход invalid → valid интеграционным сценарием.

### F-003 — Не включена обязательная архитектурная граница чтения

- Severity: medium. Category: contract. Location: `planning/tasks/STEP-003.md`, frontmatter `architecture_refs`; `docs/architecture.md#security-boundaries`.
- Scenario: implementation plan определяет parsing недоверенных workspace files и запрет чтения symlink за root, но explicit architecture refs включают components, state и reliability, не включая раздел `Security boundaries`, который задаёт post-resolution containment.
- Impact: изменение этого архитектурного контракта не инвалидирует `context_basis` плана; исполнитель может не увидеть обязательное ограничение чтения при последующих правках архитектуры.
- Fix direction: добавить `docs/architecture.md#security-boundaries` в `architecture_refs`, пересчитать planning fingerprints и провести новый независимый review изменённого плана.
