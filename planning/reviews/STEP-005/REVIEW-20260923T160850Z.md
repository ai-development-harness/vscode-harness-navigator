## Findings

### F-001 — RangeError в rebuild из-за push(...referencesForFile()) при ~125k+ ссылок в одном файле ломает активацию

**Severity:** medium
**Category:** implementation
**Location:** src/projectModel/artifactIndex.ts: collectReferences (references.push(...this.referencesForFile(...))), вызывается из rebuild и ProjectStateService.refreshRoot
**Scenario:** Harness-aware Markdown размером меньше 1 MiB с ~125000 упоминаний одного ID: spread такого числа аргументов бросает RangeError (120000 проходит, 125000 падает). Код существует на HEAD (STEP-003), но лежит в hot path индекса, за который отвечает STEP-005.
**Impact:** Исключение из конструктора ProjectStateService: activate падает для всех roots, views/команды/navigation providers не регистрируются; refreshRoot оставляет устаревший индекс. DoS функциональности расширения на враждебном репозитории.
**Fix direction:** Заменить spread циклом for...of (как в updatePath); добавить unit-тест: rebuild с файлом из 140k повторов проходит без исключения и referencesTo возвращает 140k.

### F-002 — RangeError в updatePath из-за spread diagnostics в splice при большом числе unknown-ID references

**Severity:** medium
**Category:** implementation
**Location:** src/projectModel/artifactIndex.ts: updatePath (this.diagnostics.splice(0, n, ...filter)), аналогично materializeCandidates и applyRequirementStatuses; рост — rebuildReferenceDiagnostics (по одному diagnostic на упоминание)
**Scenario:** После rebuild в this.diagnostics более ~120k элементов (например 2 файла по 70k упоминаний неизвестного ID); следующий updatePath любого Harness Markdown бросает RangeError после фильтрации this.references, но до setFileReferences: индекс остаётся рассинхронизированным.
**Impact:** Все инкрементальные обновления индекса root ломаются до перезагрузки окна; lookup-Map расходятся с references (устаревшие позиции definition/references/relations).
**Fix direction:** Убрать spread из splice (переприсвоение через filter либо фильтрация на месте); дедуплицировать reference-diagnostics по (file, targetId) или ограничить их число; unit-тест: rebuild с ≥130k unknown references, затем updatePath другого файла.
