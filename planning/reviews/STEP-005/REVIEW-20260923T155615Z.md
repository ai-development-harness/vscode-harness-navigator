## Findings

### F-001 — Квадратичная сложность setFileReferences в ArtifactIndex.updatePath блокирует Extension Host

**Severity:** medium
**Category:** implementation
**Location:** src/projectModel/artifactIndex.ts: ArtifactIndex.setFileReferences (вызывается из updatePath)
**Scenario:** Harness-aware Markdown меньше 1 MiB с десятками тысяч повторов одного ID (например `STEP-1`) приходит через git pull или сохранение и вызывает updatePath. Для каждой старой reference заново фильтруется весь referencesByTargetId[targetId], для каждой новой список копируется spread-ом: O(k^2). Замер security-reviewer: 80 тыс. повторов (~560 KB) — 40 с синхронной работы updatePath против 76 мс на HEAD; rebuild остаётся линейным (96 мс).
**Impact:** Синхронная блокировка общего Extension Host (зависают hover, completion, команды всех расширений) при каждом изменении такого файла; performance-critical регресс, вносимый этим STEP; обходит смысл лимита MAXIMUM_MARKDOWN_SIZE_BYTES.
**Fix direction:** Сделать инкрементальное обновление линейным: собрать множество затронутых targetId из старых и новых reference файла, для каждого targetId один раз пересобрать список (отфильтровать file !== changed и добавить новые, сгруппированные по targetId) без spread в цикле; либо вызвать линейный reindexReferences() после обновления this.references. Добавить unit-тест с бюджетом времени updatePath для файла с десятками тысяч повторов одного ID.

### F-002 — Нет теста на отсутствие повторного scan в hot paths

**Severity:** low
**Category:** evidence
**Location:** tests/unit/artifactIndex.test.ts, src/test/integration/navigation.test.ts
**Scenario:** Ни один тест не проверяет прямо, что hover, completion и references не вызывают rebuild, markdownFiles или snapshot(); регрессия (вызов snapshot() в provider) не будет поймана.
**Impact:** Запрет Mutation policy на повторный scan защищён только code review.
**Fix direction:** Unit-тест со счётчиком вызовов rebuild и snapshot вокруг referencesTo/artifactIds (можно вместе с исправлением квадратичного updatePath).

### F-003 — Integration-тест навигации — один монолитный test() со слабой проверкой токенов

**Severity:** low
**Category:** evidence
**Location:** src/test/integration/navigation.test.ts:31
**Scenario:** Все сценарии в одном test(): первый упавший assert скрывает остальные; токены проверяются как data.length===10 без проверки позиций и исключения unknown REQ-999.
