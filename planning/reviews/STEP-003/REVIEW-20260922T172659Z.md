## Findings

### F-011 — Directory ancestor swap остаётся возможен после повторной проверки

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/artifactIndex.ts:195-219`, особенно `:211-214`; `tests/unit/artifactIndex.test.ts:191-212`

**Scenario:** `markdownFiles()` получает `Dirent` каталога, делает `realpathSync(child)` и `lstatSync(child).isDirectory()`, затем вызывает `visit(realChild)`. Если после `lstatSync` и до внутреннего `readdirSync(current)` каталог заменить symlink на внешний directory, `realChild` остаётся той же строкой пути и `readdirSync` следует уже по внешнему target. Descriptor каталога либо identity check, связывающий проверенный объект с последующим traversal, отсутствует.

**Impact:** Исправление прежнего F-003 сужает окно, но не выполняет explicit plan step 2 и architecture security boundary: scanner всё ещё может прочитать внешний directory tree и задержать Extension Host. Единственный swap test проверяет final Markdown перед `open`, а не ancestor directory перед recursion.

**Fix direction:** Закрепить traversal за проверенным directory descriptor/capability либо повторно проверить identity непосредственно вокруг открытия каждого directory без следования symlink; добавить deterministic hook/test подмены ancestor между проверкой и recursion. После исправления повторить adversarial security review.

### F-012 — Artifact relations теряют STEP dependencies и OQ affects

**Severity:** high

**Category:** implementation

**Location:** `src/projectModel/artifactIndex.ts:155-192`, особенно список relation keys `:178`; `tests/unit/artifactIndex.test.ts:65-106,226-235`

**Scenario:** Parser извлекает только `requirements`, `adrs`, `steps`, `supersedes`, `superseded_by`. Canonical STEP использует `depends_on`, а OQ — `affects`. На текущем workspace независимый probe вернул для STEP-003 только REQ/ADR relations и не включил dependency STEP-002; `STEP-002.incomingRelations` также не содержит STEP-003. OQ с `affects: [STEP-003]` аналогично не создаст outgoing/backlink relation.

**Impact:** Acceptance STEP-003 и REQ-003 требуют outgoing/incoming relations для корректных STEP, REQ, ADR и OQ. Consumers общего Artifact Index получают неполный graph, поэтому dependency/focus/navigation features будут давать неверный результат, даже если Reference Index видит текстовый ID.

**Fix direction:** Включить artifact-kind-aware canonical relation fields как минимум `depends_on` и `affects`, сохраняя допустимые targets (`PROJECT` не является Artifact ID); пересобирать backlinks инкрементально. Добавить STEP dependency и OQ affects tests вместе с invalid-target diagnostics.

### F-013 — Artifact watcher не проходит реальный EN/RU Extension Host gate

**Severity:** high

**Category:** implementation

**Location:** `src/projectModel/projectStateService.ts:87-126`; `src/test/integration/extension.test.ts:137-207,248-254`

**Scenario:** Integration test создаёт STEP-900, выполняет Refresh, меняет тот же файл на STEP-901 и ожидает индекс без restart. Два независимых запуска вне sandbox оба завершились exit code 1: в первом English дал 5 passing/1 failing, Russian — 6 passing; во втором English — 6 passing, Russian — 5 passing/1 failing. Оба failure произошли в первом `waitFor`: `watcher did not publish expected derived state`. Трёхсекундный polling не увидел STEP-901.

**Impact:** Главный integration Acceptance STEP-003 и REQ-009 не является надёжно выполненным: допустимое изменение artifact иногда теряется до Refresh. Локаль не должна влиять на business logic; чередование locale показывает lifecycle/event race, а не локализованный контракт.

**Fix direction:** Устранить race создания/замены watchers при `refreshRoot` и предоставить наблюдаемый момент готовности либо сохранить событие во время перехода; не полагаться на фиксированную задержку 250 ms. Сделать сценарий детерминированным и потребовать два полностью зелёных EN/RU Extension Host запуска.
