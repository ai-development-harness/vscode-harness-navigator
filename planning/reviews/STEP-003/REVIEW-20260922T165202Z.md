## Findings

### F-001 — Reader REQ lifecycle не читает реальную status projection

**Severity:** high

**Category:** implementation

**Location:** `src/projectModel/artifactIndex.ts:389-404`; `docs/requirements/STATUS.md:5-15`; `tests/unit/artifactIndex.test.ts:58-66`

**Scenario:** Реальная проекция Harness содержит строку `| [REQ-001](REQ-001-read-only-source-of-truth.md) | Название | partial | ... |`. Regex требует голый `REQ-NNN` сразу после `|` и берёт соседний столбец как status. Поэтому ни одна текущая строка не совпадает; у REQ status остаётся `undefined` или frontmatter `status`, хотя canonical REQ не владеет lifecycle. Unit fixture использует искусственную двухколоночную таблицу, которой нет в проекте.

**Impact:** Acceptance STEP-003 и REQ-003 нарушены на собственном workspace; индекс не отражает `planned`, `partial` и прочие lifecycle статусы из единственного допустимого источника.

**Fix direction:** Разбирать фактические колонки generated requirements projection, ID из Markdown-ссылки и третий столбец статуса; malformed projection диагностировать. Проверить reader на реальной структуре `STATUS.md` и не брать lifecycle из REQ frontmatter.

### F-002 — FIFO и неограниченное чтение Markdown способны остановить Extension Host

**Severity:** high

**Category:** implementation

**Location:** `src/projectModel/artifactIndex.ts:93-130`, особенно `openSync`/`readFileSync`; `tests/unit/artifactIndex.test.ts:162-185`

**Scenario:** После pre-open `realpathSync`/`lstatSync` недоверенный файл подменяется FIFO перед `openSync`. `O_RDONLY` без `O_NONBLOCK` может ждать writer бесконечно, ещё до descriptor identity проверки. Большой regular Markdown читается целиком через `readFileSync` без лимита.

**Impact:** Одно изменение workspace блокирует Extension Host или расходует память, нарушая fail-safe parsing, изоляцию ошибок и reliability contract. Зелёный symlink-swap test не покрывает FIFO либо размер.

**Fix direction:** Добавить неблокирующее открытие на поддерживаемой platform, проверку regular descriptor до чтения и ограничение объёма Markdown; недопустимый input превращать в recoverable diagnostic. Добавить FIFO-swap и oversized regression с ограниченным временем.

### F-003 — Recursive scan доверяет устаревшему Dirent при подмене вложенного каталога

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/artifactIndex.ts:199-216`

**Scenario:** `readdirSync(current, {withFileTypes:true})` сообщает, что вложенный entry — каталог. До `visit(child)` его заменяют symlink на внешний каталог. `visit` делает `readdirSync(child)` уже по symlink и обходит внешнее дерево; для каждого вложенного entry containment повторно не доказан. File read seam позже может отклонить внешний файл, но внешний каталог уже прочитан и рекурсия может быть дорогой.

**Impact:** Нарушены explicit plan step 2 и security boundary архитектуры: scanner выходит за owning workspace и может задержать Extension Host на внешнем дереве.

**Fix direction:** Повторно доказывать containment каждого открываемого directory entry с no-follow/identity или иным ограниченным directory traversal; не следовать symlink после Dirent check. Добавить deterministic ancestor-swap regression для scan.

### F-004 — Watcher игнорирует разрешённые configured paths вне docs/planning

**Severity:** high

**Category:** implementation

**Location:** `src/projectModel/projectStateService.ts:87-99`; `src/projectModel/artifactIndex.ts:337-350`

**Scenario:** Валидный manifest задаёт `protocol.taskDirectory: project/tasks` или `sources.requirements: spec/requirements`, оба содержатся в workspace. Initial `ArtifactIndex.rebuild` читает их, но watcher создан только для `{planning,docs,.harness}/**/*.md`. Изменение такого STEP либо `spec/requirements/STATUS.md` не вызывает `updatePath`.

**Impact:** Индекс и статусы остаются устаревшими до ручного Refresh вопреки manifest-driven paths, STEP-003 Acceptance и REQ-009 incremental contract.

**Fix direction:** Создавать watcher coverage из проверенных configured roots/projections, сохранив фильтр Harness-aware files и отсутствие обхода `node_modules`; покрыть нестандартные contained paths integration/unit scenario.

### F-005 — Classifier и Reference Index пропускают дополнительный Harness Markdown и дублируют совпавшие файлы

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/artifactIndex.ts:54-79,407-438`; `tests/unit/artifactIndex.test.ts:190-201`

**Scenario:** `docs/guides/usage.md` внутри Harness workspace, но вне четырёх canonical directories и пяти перечисленных файлов, отвергается classifier, несмотря на explicit Acceptance об additional Markdown. При обычной конфигурации `planning/tasks/STEP-001.md` сканируется дважды — через `taskDirectory` и `planning`; совпавшие projections могут повториться по той же причине.

**Impact:** Reference Index пропускает допустимые упоминания и создаёт дубли для других; future reference/navigation consumers получат неполные либо повторённые результаты.

**Fix direction:** Формально ограничить Harness workspace по detection/manifest, включить additional Markdown внутри него при исключении Markdown вне области, дедуплицировать файлы перед parsing. Проверить both inclusion/exclusion и точное число references.

### F-006 — Изменение duplicate artifact оставляет неконсистентный индекс и diagnostics

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/artifactIndex.ts:245-255,284-312,364-387`

**Scenario:** Два файла имеют один ID. Rebuild сохраняет один и выдаёт `DuplicateArtifactId`; другой не учтён как кандидат. При удалении сохранённого файла `updatePath` просто удаляет ID и не восстанавливает оставшийся корректный artifact. При удалении duplicate файл не был в `byId`, а diagnostic с аргументом ID не удаляется фильтром по basename. Аналогично `ProjectionReadError` с пустыми arguments остаётся после успешного чтения projection.

**Impact:** Изменение одного файла может скрыть корректный artifact или оставить ложный diagnostic до полного Refresh. Инкрементальная модель нарушает согласованность и изоляцию ошибок.

**Fix direction:** Хранить кандидатов/происхождение diagnostics по файлу и пересчитывать collision group и затронутые derived diagnostics при create/change/delete; очистить `ProjectionReadError` после успешного чтения. Добавить remove/repair duplicate и projection recovery tests.

### F-007 — Проверка identity принимает filename другого ID

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/artifactIndex.ts:155-179`

**Scenario:** Файл `STEP-0010.md` содержит frontmatter `id: STEP-001` и H1 `# STEP-001 — ...`. `path.basename(file).startsWith(id)` возвращает true, поэтому файл попадает в индекс как STEP-001, хотя имя задаёт STEP-0010. Отсутствует проверка разделителя или canonical filename ID.

**Impact:** STEP-003 Acceptance требует diagnostic для ID/file mismatch; вместо этого индекс публикует неверную identity, что меняет relations и lookup.

**Fix direction:** Извлекать ID из имени по точной границе (`.md` либо разделитель slug) и сравнивать с frontmatter/H1; добавить regression для префиксного ID и ADR/OQ identity.

### F-008 — Reference Index не даёт требуемый range и не диагностирует неизвестные текстовые ссылки

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/artifactIndex.ts:26-30,263-277,441-459`

**Scenario:** Reference хранит только `file` и `offset`, но plan требует URI/range/target ID для providers. `InvalidArtifactReference` появляется лишь из frontmatter relation lists; упоминание `REQ-999` в Harness-aware Markdown остаётся в `references` без diagnostic, если его нет в Artifact Index. При update обычного reference-файла invalid-reference diagnostics также не пересчитываются.

**Impact:** Индекс не удовлетворяет интерфейсу STEP-003 и REQ-003 для неизвестных references; будущий provider не сможет использовать готовый range без повторного parsing и не получит корректную diagnostic taxonomy.

**Fix direction:** Хранить диапазон позиции/длины либо line/character range и проверять target IDs ссылок при build/update, сохраняя source ownership для инкрементальной очистки. Покрыть ADR/OQ и неизвестные текстовые упоминания.

### F-009 — Artifact diagnostics не показываются общим diagnostics flow

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/projectStateService.ts:55-77`; `src/projectModel/artifactIndex.ts:329-335`

**Scenario:** Индекс обнаруживает malformed artifact, missing directory или duplicate ID, но `Harness: Show Diagnostics` строит строки только из `this.states` и `projectState.diagnostic`. `this.indexes` и `ArtifactIndex.snapshot().diagnostics` не читаются ни одним runtime consumer.

**Impact:** REQ-008 и STEP-003 требуют безопасно отражать recoverable artifact errors; фактически ошибки остаются невидимыми пользователю даже при открытии diagnostics command.

**Fix direction:** Подключить artifact diagnostic snapshot к существующему Output Channel flow с localized keys, stable categories и безопасными details; обновлять вывод после watcher/Refresh. Проверить EN/RU runtime строки.
