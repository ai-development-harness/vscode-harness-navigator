### F-001 — Подсветка longest dependency chain пропускает все canonical рёбра из-за обратного порядка API

**Severity:** medium
**Category:** implementation
**Location:** src/projectGraph/dependencyGraphRuntime.ts:367
**Scenario:** Given Открыт Full graph без дополнительных filters на captured schema-v1 snapshot tests/unit/fixtures/dependencyGraphApi.json: longestChain содержит STEP-001, STEP-002 и далее 10 IDs; девять соединяющих depends_on рёбер направлены от зависимого STEP к dependency, например STEP-002 → STEP-001. / When Пользователь включает Longest dependency chain в toolbar. / Then Десять узлов получают class chain, но ни одно из девяти canonical рёбер цепочки не получает подсветку.
**Expected:** Подсветка предоставленной API цепочки выделяет её узлы и существующие соединяющие depends_on рёбра, сохраняя canonical source/target/type/declaredBy.
**Observed:** chainEdges строится как ordered[i] → ordered[i+1]. В актуальном API longestChain перечисляет dependency прежде зависимого STEP, а depends_on имеет обратное направление. Для captured snapshot forwardPairsFound=[], reversePairsFound содержит все 9 соседних пар; condition class chain не совпадает ни с одним canonical edge.
**Impact:** Действие longest-chain показывает отдельные выделенные узлы вместо читаемой цепочки связей. Подсветка chain graph не соответствует API facts и остаётся неполной по Acceptance о longest dependency chain; existing tests проверяют исполнение renderer, но не canonical edge highlighting на captured wire форме.
**Fix direction:** Сопоставлять соседние IDs только предоставленной API longestChain с существующими depends_on edges с учётом фактического wire direction; не менять direction или состав canonical рёбер. Добавить regression на captured API, который после toolbar action проверяет class chain у всех видимых соединяющих рёбер и отсутствие highlight у остальных рёбер.
**Fingerprint:** sha256:522aef64be55ab26ad46bfee2a89031722b64904a909840096fcbb3971debcfc

**Admissible alternatives:**
- Построить lookup для соседних API IDs и проверять canonical edge endpoints в фактическом dependency-first порядке.
- Сопоставлять существующие depends_on edges с соседними API IDs независимо от порядка пары, сохраняя исходные source/target для rendering.

**Constraints:**
- Исправление ограничено presentation/runtime и graph-focused tests текущего STEP.
- Project State API, canonical relation semantics, backend/process/cache/watch и Accepted ADR-008 не менять.
- Не вычислять альтернативную цепочку и не синтезировать reciprocal edges.
