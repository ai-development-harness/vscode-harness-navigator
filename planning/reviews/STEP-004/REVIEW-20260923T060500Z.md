Then в обоих прогонах committed fixture перед restore содержит добавленный блок, которого нет в HEAD-версии файла: `"settings": { "harnessNavigator.artifacts.sortOrder": "id" }`. **Impact:** Evidence содержит утверждение о наблюдении, которого implementer не мог получить: оно проверяемо только при отключённом restore, а при включённом restore `git status` чист по построению. **Fix direction:** Переписать абзац Evidence по факту: byte-restore в `finally` остаётся load-bearing, потому что сценарий персистит `harnessNavigator.artifacts.sortOrder` в committed fixture и не удаляет этот ключ; зафиксировать только реально полученное observation.
