## Findings

### F-001 — Prerelease ниже minimum ошибочно считается совместимым

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/manifestService.ts:159`, `tests/unit/manifestService.test.ts`

**Scenario:** Workspace сообщает `harness.release: "0.6.0-beta.1"`. `parseRelease()` принимает
prerelease suffix, но `isReleaseAtLeast()` сравнивает только `[0, 6, 0]`; фактический вызов
`detectProject()` вернул `kind: valid`, хотя SemVer prerelease предшествует стабильному minimum
`0.6.0`.

**Impact:** Неподдерживаемый pre-release Harness проходит compatibility boundary, получает
валидные configured paths и может быть прочитан последующими слоями вопреки REQ-002 и
fail-closed contract STEP.

**Fix direction:** Использовать корректное SemVer-сравнение с prerelease precedence либо
эквивалентную строгую реализацию; добавить boundary tests минимум для `0.5.9`,
`0.6.0-beta.1`, `0.6.0`, build metadata и release выше minimum.

### F-002 — Diagnostic details не локализуются

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/manifestService.ts:19`,
`src/projectModel/projectStateService.ts:27`, `l10n/bundle.l10n*.json`

**Scenario:** В русской локали пользователь открывает ordinary, malformed, unsupported либо
blocked workspace и запускает `Harness: Show Diagnostics`. Локализован только summary; все
details создаются как English literals (`Manifest is absent.`, `Unsupported Harness release`,
`Traversal paths are not allowed` и другие), а filesystem/YAML errors выводятся напрямую.

**Impact:** Основное объяснение состояния остаётся английским и не имеет localization key,
поэтому пользовательские diagnostics/errors не доступны на русском, несмотря на REQ-008 и
Acceptance STEP. Integration test наблюдает только возвращённые states и не доказывает EN/RU
текст Output Channel.

**Fix direction:** Хранить stable category плюс безопасные structured arguments, а
пользовательский текст формировать через `vscode.l10n.t` с EN/RU bundle entries; отделить
локализованное объяснение от технической detail. Добавить EN/RU observable tests diagnostics
command/output для основных состояний.

### F-003 — Ошибки отсутствующего поля и I/O попадают в неверную taxonomy

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/manifestService.ts:31`,
`src/projectModel/manifestService.ts:55`, `src/projectModel/manifestService.ts:84`

**Scenario:** Manifest без обязательного `harness.release` возвращает
`UnsupportedHarnessVersion` с detail `undefined`, а существующий, но недоступный для чтения
manifest возвращает `InvalidManifest`. Объявленная `UnexpectedInternalError` нигде не
производится. Эти результаты подтверждены прямыми вызовами `detectProject()` на current
revision.

**Impact:** Пользователь не может отличить malformed configuration, реально неподдерживаемую
версию и operational/internal read failure; stable taxonomy даёт неверные recovery hints и не
выполняет диагностируемую деградацию из REQ-008 и Implementation plan.

**Fix direction:** Валидировать отсутствие/тип обязательного release как `InvalidManifest`,
отделить YAML/schema failures от filesystem/internal failures и реально производить
`UnexpectedInternalError` с безопасной technical detail. Закрепить каждый producer unit tests.

### F-004 — Недоверенный manifest читается и парсится без resource limit

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/manifestService.ts:19`, `src/extension.ts:35`

**Scenario:** Пользователь открывает недоверенный workspace с очень большим либо патологически
сложным `.harness/manifest.yaml`. Activation синхронно выполняет `readFileSync()` всего файла и
`js-yaml.load()` без ограничения размера до возврата управления Extension Host.

**Impact:** Workspace content может надолго заблокировать или исчерпать память Extension Host;
обычный `try/catch` не делает memory/CPU exhaustion fail-safe. Это нарушает security boundary
архитектуры для недоверенных workspace files и требование не ломать Extension Host.

**Fix direction:** До чтения ввести консервативный documented maximum manifest size и
отклонять превышение безопасным typed state; исключить неограниченную синхронную parsing path и
добавить regression tests для oversized/deep input, подтверждающие controlled result.
