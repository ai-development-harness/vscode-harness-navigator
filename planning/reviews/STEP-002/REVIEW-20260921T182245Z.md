## Findings

### F-005 — Синтаксически неверный release ошибочно считается неподдерживаемой версией

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/manifestService.ts:143`,
`src/projectModel/manifestService.ts:282`, `tests/unit/manifestService.test.ts:73`

**Scenario:** Manifest содержит обязательное поле `harness.release`, но его значение не является
SemVer, например `banana`. `parseRelease()` возвращает `undefined`, однако
`isReleaseAtLeast()` сворачивает invalid format и корректную версию ниже minimum в один `false`.
Прямой вызов `detectProject()` на reviewed revision вернул `kind: unsupportedVersion` и
category `UnsupportedHarnessVersion` для `banana`.

**Impact:** Повреждённый manifest неотличим от корректного, но неподдерживаемого Harness
release. Пользователь получает неверную taxonomy/recovery подсказку, хотя REQ-002 и Acceptance
STEP требуют разных понятных состояний для malformed manifest и unsupported release.

**Fix direction:** Валидировать SemVer отдельно: invalid release format преобразовывать в
`invalidManifest`/`InvalidManifest`, а `unsupportedVersion` выдавать только корректному SemVer
ниже `0.6.0`. Добавить regression cases для не-SemVer и ведущих нулей рядом с существующими
boundary tests.

### F-006 — Non-regular manifest может навсегда заблокировать Extension Host

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/manifestService.ts:344`, `src/extension.ts:38`,
`tests/unit/manifestService.test.ts:150`

**Scenario:** Внутри workspace `.harness/manifest.yaml` является FIFO. Activation синхронно
вызывает `detectProject()`, а `readBoundedManifest()` выполняет blocking `openSync(path, 'r')`
до `fstatSync()` и до любого resource check. Контролируемый probe на reviewed revision не
вернулся за одну секунду, не напечатал typed state и был остановлен `timeout` с exit code `124`.

**Impact:** Недоверенное содержимое workspace может повесить единственный Extension Host ещё
при активации; `try/catch`, лимит размера и deep-YAML regression здесь не исполняются. Это
нарушает fail-safe parsing/security boundary и требование REQ-008 не ломать Extension Host.

**Fix direction:** До blocking read исключить non-regular filesystem nodes и проверить тип
фактически открытого descriptor безопасным non-blocking способом; вернуть controlled typed
state для FIFO/socket/device. Добавить изолированный regression с жёстким timeout, чтобы сам
test runner не мог зависнуть.
