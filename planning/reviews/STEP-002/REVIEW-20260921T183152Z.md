## Findings

### F-007 — Новые сообщения malformed/non-regular manifest не локализованы

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/manifestService.ts:150`,
`src/projectModel/manifestService.ts:357`, `src/projectModel/manifestService.ts:373`,
`l10n/bundle.l10n.ru.json:1`, `tests/unit/manifestService.test.ts`

**Scenario:** В русской локали workspace содержит `harness.release: banana`, directory/FIFO вместо
manifest либо manifest больше 64 KiB, после чего пользователь запускает
`Harness: Show Diagnostics`. Эти ветви передают в `vscode.l10n.t` строки
`Harness manifest contains an invalid release: {0}.`, `Harness manifest must be a regular file.`
или динамический `Harness manifest exceeds 65536 bytes.`, но соответствующих keys нет ни в
English fallback bundle, ни в RU bundle. VS Code поэтому показывает английский fallback в
русском UI. Существующий localization unit test проверяет только отношения между уже
перечисленными keys и не сверяет production message keys с bundles; integration fixture
наблюдает только `Harness manifest is absent.`.

**Impact:** Исправленные F-005/F-006 и часть F-004 нарушают REQ-008 и Acceptance STEP о RU/EN
diagnostics: техническая category стабильна, но пользовательское объяснение malformed или
blocked состояния остаётся нелокализованным. Green EN/RU integration gate не обнаруживает этот
observable regression.

**Fix direction:** Использовать стабильные literal localization keys с arguments для invalid
release, non-regular и oversized manifest, добавить их в EN/RU runtime bundles и расширить тест,
который сверяет production keys с bundles и наблюдает хотя бы эти исправленные ветви в русской
локали.

### F-008 — Проверенный manifest можно заменить symlink между containment check и open

**Severity:** medium

**Category:** implementation

**Location:** `src/projectModel/manifestService.ts:43`,
`src/projectModel/manifestService.ts:355`, `src/projectModel/manifestService.ts:364`

**Scenario:** При активации `realpathSync(manifestPath)` и последующий `lstatSync(realManifest)`
проверяют contained regular file. Если concurrent process после этих проверок заменяет этот path
symlink-ом на regular файл вне workspace, `openSync(..., O_RDONLY | O_NONBLOCK)` следует за
symlink. `fstatSync()` видит regular descriptor и принимает его; размер и YAML проверяются уже у
внешнего файла. Комментарий о защите от замены между `lstat` и `open` не соответствует
фактическим flags: no-follow/descriptor identity check отсутствует.

**Impact:** Явная security boundary REQ-002/architecture допускает чтение за owning workspace
root через TOCTOU race. Даже без network или mutation это нарушает read-only trust boundary и
может превратить локальный внешний файл в derived project state/diagnostic data.

**Fix direction:** Открывать manifest с доступной на платформе no-follow семантикой и проверять
containment/identity фактически открытого descriptor-а, закрыто деградируя на platforms без
надёжного primitive. Добавить изолированный regression, который детерминированно заменяет path
между validation и open и доказывает, что внешний target не читается.
